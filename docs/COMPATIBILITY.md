官方 API 只保证自己的插件设置分区，不提供“接管 EUI 所有尺寸与替换原控件”的公开协议。其文档还明确排除私有字段与原生函数钩子。因此本项目不能把“设置页已正式注册”包装成“整款插件获得官方支持”。没有改 EUI 源码、替换原函数或绕过注册保护，但仍存在不受官方支持的私有依赖。

用户已确认：原尺寸入口改为档位，是核心，不做双输入降级。若实机受阻，修正版本适配或争取上游公开扩展点；不得绕过上游保护、删除核心要求后声称完成。测试包不等于完成发布。

## 下次更新怎么验证

1. 核对官方发行源码：字段含义、刷新生命周期、原控件结构、游戏限制；不能只看函数是否还存在。
2. 相同契约复用适配器；变化才改对应层。私有接口只允许明确核验过的版本，混装模块不自动放行。
3. 检查旧数据迁移、恢复来源和外部冲突；跑 `npm run package`，再逐项做实机验收。

v9.4 源码证据固定在 `contracts/eui-9.4.json`，记录 24 个文件的 Git blob SHA；不包含上游源码。可对官方检出目录或本次缓存目录进行只读完整性核验：

```sh
npm run audit:upstream -- /absolute/path/to/EUI-source
```

哈希通过仅说明源码与审阅基线一致，不能证明行为或实机兼容。临时缓存 `/private/tmp/eui-compat-audit.bvathQ` 可能被清理；缺失时重新获取固定 tag，不能用 main 冒充。
